# AstrBot v4.29.4 覆盖与验收边界

基线：AstrBot `v4.29.4`，宿主源码 `61335414433db721b3f7ecc93f90deafe0a59d78`。结论分为**源码确认**和**实测**。这里的“检查完成”只指已选文本扫描完成，不代表整份模型输入安全。

## 请求字段

以宿主 `astrbot/core/provider/entities.py` 的 `ProviderRequest` / `assemble_context`、`astrbot/core/agent/runners/tool_loop_agent_runner.py` 及插件 `request_input.py` / `main.py` 为准。

| 字段或来源 | 宿主用途 | 插件覆盖 |
| --- | --- | --- |
| `prompt` | 当前用户文本，组装进用户消息；可能已被宿主或插件加工 | 本地规则检查副本。只有事件 `message_str` 与请求完全相同、且整条消息由相同纯文本组件组成，才作为可归责文本和复核候选。 |
| `extra_user_content_parts` | `ContentPart` 或字典，添加到当前用户消息；可能包含系统提醒、插件、引用、检索文本或媒体 | `scan_extra_text` 开启时，支持的文本形态逐块做本地规则检查。宿主字段不带可靠来源证明，混合文本不发给复核模型、不作用户诊断原文、不凭它处罚。无法完成必要复核时按故障策略处理。其他形态不覆盖。 |
| `image_urls`、`audio_urls`、额外媒体块 | 媒体引用可由宿主读取、转换或组装进模型消息 | 不读内容、不解码媒体、不做 OCR／转录、不抓取 URL。不把“文本检查完成”写成媒体检查通过。存在不透明媒体来源会限制处罚归责。 |
| `system_prompt` | 内置 runner 作为系统消息插入 | 不做规则、语义或完整性检查。不记录完整系统提示；`harden` 只附加固定可信提醒。 |
| `contexts` | 历史、上下文及检查点，经 runner 组装；也可能带外部文本或旧工具消息 | 不遍历、不反复处罚历史、不做完整性校验。检索或引用实际进入 `prompt` 或已支持额外文本的，仅按相应文本路径处理。 |
| `func_tool` | 提供模型可用工具定义及执行注册信息 | 不检查定义或执行权限，不授予、剥夺工具权限，不提供逐工具执行拦截。复核调用不携带工具。 |
| `tool_calls_result` | 初始请求可附带已有工具调用结果；runner 还可在后续循环加入新的结果 | 不读结果，也不对后续循环重新触发本插件的请求检查。有不透明的随请求工具结果时不作处罚归责。 |
| `conversation` | 宿主会话对象，关联历史、持久化和人设 | 不扫描对象或历史；显式匹配的人设只作非处罚建议。 |
| `session_id`、`model` | 会话关联与主请求模型选择，不是用户消息正文 | 不扫描，不作为认证凭据。复核 Provider／模型按单独配置和宿主会话选择。 |
| 原始事件、后续加工和未知字段 | 后续代码仍可读取原始消息、缓存或附加数据 | 事件纯文本只用于来源核对；其他字段及后续修改不覆盖。 |

没有仅做完整性校验的字段：新版移除了跨钩子的签名锁，没有以会话 ID 存放请求快照。分析与复核在一次钩子调用内关联，诊断 ID 独立生成；不宣称签名、优先级或文本相同能证明权限。字段未覆盖、来源不可归责和扫描预算耗尽是不同情况。

## 钩子、阻断与隔离

1. `star/star_handler.py` 按 `priority` 降序注册排序；`pipeline/context_utils.py::call_event_hook` 依序执行适用 handler，发现 `event.is_stopped()` 后返回停止。插件只注册一个 `on_llm_request(priority=-1000)`，优先级较低不代表绝对最后。
2. 默认内置 Agent 的 `agent_sub_stages/internal.py` 收到停止后直接返回，未继续该次请求的后置图片准备、延迟 runner 初始化或主模型生成。`third_party.py` 也在外部 runner 创建和 `reset` 前检查停止，属源码结论，未实测远端 Agent。先于钩子的宿主加工、其他插件自行发出的请求及不进入该调用链的入口不在保证范围。
3. `scorch` 在没有可证明的完整隔离路径时实际阻断：`request_input.isolate` 当前恒为 `False`，保留原对象不改。宿主在请求钩子后还有图片处理和 runner 初始化，后续代码也可读取原事件。清空当前几个字段不足以排除重新引入原内容，不能称为替换成功。
4. `astr_agent_hooks.py::MainAgentHooks.on_tool_start` 调用工具开始钩子，但不消费其停止返回值。`tool_loop_agent_runner.py` 接着调用 `tool_executor.execute`，不以该钩子返回或事件停止作为执行前授权闸门。主请求已停、工具未开始，与已启动的 Agent 在某个工具调用前拒绝执行是两个不同保证；本插件不声称后者。

## 权限

| 操作 | 源码确认 |
| --- | --- |
| 聊天命令修改配置、模式、观察、名单及诊断 | `access.admin_command` 同时使用宿主 `PermissionType.ADMIN` 和处理器入口的 `event.is_admin()`。宿主醒来检查从 `admins_id` 标记管理员角色，`is_admin()` 检查该事件角色。平台群管理员身份、昵称、关系和检测白名单均不授予命令权限；管理员状态与帮助为只读。 |
| 名单豁免、观察和关闭检测 | 当前实现先查有效封禁，再考虑管理员／白名单检测豁免、防护开关或观察。观察只改变检测处置，不覆盖已有硬限制，也不发起自动处罚。工具真实权限仍由宿主管理。 |
| Dashboard API 与设置页面 | 宿主插件页面和官方 bridge 提供页面资源和请求通道，经 `Context.register_web_api` 注册。Dashboard `/api/plug/...` 由 `require_dashboard_user` 认证；插件还校验登录身份、插件命名空间、拒绝平台 OpenAPI 密钥身份和演示模式，并验证方法、JSON、字段范围、写入确认和配置 revision。使用宿主 Dashboard 权限，不等同于聊天管理员。插件未另外开启 HTTP 监听或签发登录令牌。 |
